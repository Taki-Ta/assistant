# 知识库结构与权限

```text
知识空间（虚拟根节点）
└─ KnowledgeBase
   └─ Document
      └─ Chunk
         └─ VectorRecord（索引数据，不作为界面树节点）
```

根节点不持久化，展示当前用户拥有或获授权的知识库。知识库是权限边界，文档和分段继承权限。
`documents.owner_id` 保留为上传者记录，不再作为读取权限条件；上传者失去知识库权限后也不能读取文档。
所有者由 `knowledge_bases.owner_id` 指定，其他成员存入 `knowledge_base_members`。

| 角色 | 读取、检索 | 上传、索引 | 修改库信息、管理成员 | 删除知识库 |
| --- | --- | --- | --- | --- |
| viewer | 是 | 否 | 否 | 否 |
| editor | 是 | 是 | 否 | 否 |
| admin | 是 | 是 | 是 | 否 |
| owner | 是 | 是 | 是 | 是 |

所有者不能通过成员接口降级或删除。知识库删除采用软删除，立即排除在读取和检索范围之外。
默认知识库不能删除。当前不提供所有权转移、文档级权限、公开链接或用户邀请流程；
成员接口接收现有认证系统的用户身份标识，系统尚无本地用户目录。

## 迁移

新数据库先执行 `migration/init_sql`（或同内容的 `001_create_chunks_and_vectors.sql`，二选一），
再依次执行 `002_create_agent_conversations.sql`、`003_create_user_preferences.sql`、
`004_create_knowledge_bases.sql`。已有数据库只执行尚未执行的增量脚本。

004 在单个事务中建立知识库及成员表，为每个已有文档上传者建立默认知识库，
回填 `documents.knowledge_base_id`，然后添加 NOT NULL、外键和索引。
默认知识库 ID 使用 `md5('default-knowledge-base:' || owner_id)::uuid`，
运行时也使用相同计算方式，确保迁移与新上传一致。没有文档的用户在首次上传时创建默认库。
文档、分段和向量 ID 不变，无需重新生成向量。迁移会修改文档表，应安排维护窗口并先备份。

## 接口

- `GET /api/v1/knowledge-bases`：当前用户可读的知识库。
- `POST /api/v1/knowledge-bases`：创建知识库，提交 `name`、`description`。
- `GET/PATCH/DELETE /api/v1/knowledge-bases/{id}`：读取、修改信息、软删除。
- `GET /api/v1/knowledge-bases/{id}/members`：管理者查看成员列表；所有者记录在知识库实体中。
- `PUT /api/v1/knowledge-bases/{id}/members/{user_id}`：设置 viewer/editor/admin。
- `DELETE /api/v1/knowledge-bases/{id}/members/{user_id}`：撤销成员访问权限。
- `GET /api/v1/documents?knowledge_base_id={id}`：树中知识库下面的文档。
- `POST /api/v1/documents`：上传 Markdown，表单可传 `knowledge_base_id`；省略时归入个人默认库。
- `GET /api/v1/documents/{id}`：读取文档。
- `GET /api/v1/documents/{id}/chunks`：按 `sort_index` 读取分段。
- `POST /api/v1/documents/{id}/index`：需要编辑权限。

检索查询在 Top-K 之前按当前知识库权限过滤。聊天检索工具、文档读取及旧来源回查共用权限条件。
未知和无权访问的单个资源统一返回 404。文档列表查询没有权限时返回空列表。
撤权影响后续读取和检索；已经写入个人会话的回答、工具输出和来源快照作为历史记录保留，
不会追溯删除。用户偏好及个人会话不会随知识库共享。

当前只提供数据库和后端层级接口，前端树形导航尚未实现。
