# 会话接口

所有接口使用 `Authorization: Bearer <token>`，Token 的非空 `sub` 是用户标识。
只访问当前用户未删除的会话；不存在、已删除、属于其他用户的会话统一返回 404。

## 列出会话

`GET /api/v1/sessions?limit=20&cursor=...`

- `limit` 默认为 20，范围 1–100。
- 首次请求省略 `cursor`；后续使用上页的 `next_cursor`，不要自行解析或构造。
- 会话按 `updated_at`、`id` 倒序排列。
- 游标是分页位置，不是固定快照；聊天更新会话后，前端应刷新侧栏首页。

```json
{
  "items": [
    {
      "id": "01900000-0000-7000-8000-000000000010",
      "title": "如何构建知识库？",
      "created_at": "2026-10-10T08:00:00Z",
      "updated_at": "2026-10-10T08:01:00Z"
    }
  ],
  "next_cursor": null
}
```

`next_cursor: null` 表示没有下一页。旧会话的 `title` 可能为空，前端可显示“新会话”。
聊天时，空标题使用当前提问生成：合并空白后截取前 80 个字符，不调用模型。
新增轮次和轮次结束时更新会话时间。

## 获取会话信息

`GET /api/v1/sessions/{session_id}`

返回会话的 `id`、`title`、`created_at`、`updated_at`，不包含消息正文。

## 获取历史轮次

`GET /api/v1/sessions/{session_id}/turns?limit=20&cursor=...`

- `limit` 默认为 20，范围 1–100，按轮次计数。
- 首次请求获取最近的轮次，但每页按 `sequence` 正序返回。
- 后续使用 `next_cursor` 获取更早的轮次，将结果追加到现有历史前面。
- `cursor` 是非负轮次序号，查询严格早于该序号的轮次；最大值为 2147483647。
- 同一轮次的展示项全部返回，按展示项 `sequence` 正序排列。
- 历史查询独立于模型上下文构建，不受摘要覆盖边界影响，不返回压缩摘要或推理项。

```json
{
  "items": [
    {
      "id": "01900000-0000-7000-8000-000000000011",
      "sequence": 0,
      "status": "completed",
      "created_at": "2026-10-10T08:00:00Z",
      "completed_at": "2026-10-10T08:01:00Z",
      "error_message": null,
      "items": [
        {
          "id": "01900000-0000-7000-8000-000000000012",
          "sequence": 0,
          "type": "message",
          "role": "user",
          "text": "如何构建知识库？"
        },
        {
          "id": "01900000-0000-7000-8000-000000000013",
          "sequence": 1,
          "type": "message",
          "role": "assistant",
          "text": "可以先整理文档，再进行切分和索引。"
        }
      ]
    }
  ],
  "next_cursor": null
}
```

展示项均包含 `id`、`sequence`、`type`：

| 类型 | 其他字段 |
| --- | --- |
| `message` | `role`、`text` |
| `function_call` | `call_id`、`tool_name`、`arguments` |
| `function_call_output` | `call_id`、`tool_name`、`output`、`succeeded`、`sources` |

工具调用和结果用 `call_id` 对应。来源字段与聊天完成事件的来源字段一致；前端可以
合并成功工具结果的来源，按 `chunk_id` 去重，重复项保留分数最高的一项。
新记录保存完整来源快照，旧记录批量读取当前文档切块补齐，已不存在的旧来源省略。

轮次状态包括 `in_progress`、`completed`、`failed`、`cancelled`。失败轮次返回安全的
`error_message`，不暴露数据库内的原始异常。当前聊天实现将断开/停止记录为 `failed`。
文本增量不逐段入库，工具与完整助手消息在轮次收尾时保存，因此进行中的历史并非实时
快照，中断时尚未形成完整消息的部分回答在刷新后不能恢复。

## 删除会话

`DELETE /api/v1/sessions/{session_id}`

成功返回 204，无响应体。使用 `is_deleted` 软删除，保留轮次和展示项；删除后查询或
继续聊天均返回 404，重复删除同样返回 404。

## 前端调用顺序

1. 加载侧栏时查询会话列表。
2. 选择会话时获取会话信息和最新一页轮次；向上滚动加载更早记录。
3. 新建会话先清空页面，首条 `POST /api/v1/chat/stream` 不传 `session_id`。
4. 收到 `started` 保存 `session_id`、`turn_id`，后续请求复用该会话 ID。
5. 实时文本和工具状态使用 SSE 更新；轮次完成、失败或停止后刷新会话列表。
